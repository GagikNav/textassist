# Text Assist — Agent Workflow

The canonical, harness-agnostic loop every agent follows in this repo. Read
`AGENTS.md` first (project constraints), then this file (process). Nothing here is
Copilot-specific: any harness with a terminal and file access can follow it.

## 1. Where things live

| Concern | Location | Notes |
|:--|:--|:--|
| Tasks | GitHub issues (`GagikNav/textassist`) | Epics are parent issues; tasks are native **sub-issues**. |
| Machine state | `agent:*` labels | Exactly one state label per issue. Source of truth. |
| Human board | GitHub Project (auto-detected) | Status field mirrors the labels. |
| Handoff / memory | `Docs/handoffs/issue-<n>-<slug>.md` | Git-tracked, committed with the change. |
| Mirror | Idempotent comment on the issue | Same content, for readers in GitHub. |
| Overview | `Docs/status/OVERVIEW.md` + `Docs/handoffs/INDEX.md` | Generated by `Scripts/agent/overview.sh`. |
| Session scratch | `.agents/state/session.md` | Git-ignored, ephemeral. Never the source of truth. |
| Config | `.agents/config.json` | Labels, milestones, issue map, `maxDepth`. |

## 2. The loop (state machine)

```
INTAKE → CONTEXT → PLAN → (DELEGATE) → IMPLEMENT → VERIFY → REVIEW → HANDOFF → SYNC
```

States, as labels: `agent:ready` → `agent:in-progress` → `agent:review` → `agent:done`,
plus `agent:blocked` whenever an unmet dependency exists.

| Phase | Who | Skill | Output |
|:--|:--|:--|:--|
| INTAKE | orchestrator | `pickup-task` | Readiness check: deps closed, DoR met, branch created. |
| CONTEXT | explorer (subagent) | `context-brief` | Context brief: files, patterns, constraints, risks, verification plan. |
| PLAN | orchestrator | — | Filled Plan section in the handoff doc. |
| DELEGATE | orchestrator | `delegate-subissue` | One child orchestrator per open sub-issue (unless leaf). |
| IMPLEMENT | implementer | — | The change, on the task branch. |
| VERIFY | implementer | — | Build check run; "Done when" checked by hand. |
| REVIEW | reviewer (subagent) | `review-change` | Review report against "Done when" + constraints + scope. |
| HANDOFF | orchestrator | `write-handoff` | Handoff doc committed, mirrored to the issue, labels synced. |
| SYNC | orchestrator | `sync-overview` | Overview/index regenerated; PR closed the issue. |

**Manual test instructions are mandatory.** At the end of every step — and every phase —
the agent reports **how a human can verify the result by hand**: the exact actions to
take (with the app to use) and the expected outcome. If a result cannot be tested yet,
say so and say why. The handoff's §5 collects the final, complete set; the reviewer
checks that it is present and accurate.

## 3. Roles

- **orchestrator** — owns an issue, plans, delegates, aggregates, syncs state. **Never
  implements work that belongs to an open sub-issue**; it delegates instead.
- **explorer** — read-only. Produces one context brief. Cannot edit files.
- **implementer** — makes the change for a single leaf task. Cannot delegate.
- **reviewer** — read-only, fresh context. Verifies against "Done when", the
  `AGENTS.md` hard constraints, and scope creep. Runs the build.

Definitions live in `.agents/agents/*.agent.md`.

## 4. Delegation (recursive)

1. On any issue, list its open sub-issues (`Scripts/agent/delegate.sh <epic#>`).
2. If sub-issues exist, delegate **each** to a child orchestrator running this same
   loop. The parent does not do child work; it tracks and aggregates.
3. A **leaf** task (no sub-issues) is where implementation happens.
4. `maxDepth` is **2** (`config.json`): epic (depth 0) → task (depth 1) → its children
   (depth 2, must be leaves). Stop and report if a cycle or deeper nesting is found.
5. Never delegate a task from the `sequentialTasks` list while another
   `sequentialTasks` task is in progress — they touch the same file.

## 5. Parallelism

- **One worktree per task.** Every task runs in its own git worktree
  (`build/worktrees/issue-<n>-<slug>`) on its own branch, so parallel agents never
  touch each other's files or checkout. Create it with
  `Scripts/agent/worktree.sh <n>`, or start in one step with
  `Scripts/agent/pickup.sh <n> --start`.
- Read-only subagents (explorer, reviewer) run in parallel and in any order.
- Writers serialise per file *within* a worktree. Across worktrees they are isolated;
  only the `SummarizationOrchestrator.swift` tasks (`T3.5`, `T4.4`, `T6.1`, `T6.2`)
  must still run **one at a time, in order** (they collide at merge otherwise).
- One branch/PR per leaf task.

## 6. Git policy and worktrees

- **Always work in a worktree, never in the main checkout.**
  `Scripts/agent/worktree.sh <n>` creates `build/worktrees/issue-<n>-<slug>`
  (gitignored) on a new branch `issue-<n>-<slug>` off the latest `main`, or checks out
  the existing branch. All edits, builds, commits and handoffs happen there.
- One task = one reviewable change = one PR. Squash-merge.
- PR body from `.agents/templates/pr-body.md`; it references the issue and the handoff.
- The handoff doc is committed on the same branch, so the merged commit carries its own memory.
- Remove the worktree after merge: `Scripts/agent/worktree.sh <n> --remove`.
- **Never edit** `TextAssist.xcodeproj/project.pbxproj` (file-system-synchronized group).
- Run the build check before declaring any task done:
  `xcodebuild build -project TextAssist.xcodeproj -scheme "Text Assist" -configuration Debug -destination "platform=macOS" -derivedDataPath build/DerivedData`

## 7. Definition of Ready (DoR)

A task may enter `agent:in-progress` only when:
1. It has **Depends on**, **Files**, and **Done when** in the issue body.
2. Every issue in **Depends on** is closed.
3. It has exactly one `size:`, one `area:`, one `kind:task`, one `epic:` label.
4. It is a leaf task (no open sub-issues); otherwise it is delegated first.
5. A worktree exists for it (`Scripts/agent/worktree.sh <n>`), and work happens there.

## 8. Definition of Done (DoD)

1. Build check passes (paste the command result summary in the handoff).
2. Every "Done when" item checked by hand in the running app.
3. The handoff's **How to test manually** section is filled with copy-pasteable steps
   and expected results.
4. Reviewer subagent reports no blocking findings (or findings are resolved).
5. Handoff doc written, mirrored to the issue, committed on the worktree's branch.
6. Labels set to `agent:done`; Project status synced; overview regenerated.
7. PR merged (state flips on merge), then the worktree is removed.

## 9. Resume protocol (any session, any model)

At the start of a session, run the `resume-session` skill (`/resume`):

1. `gh issue list --label agent:in-progress` and any open PRs.
2. `git status`, current branch, `Docs/status/OVERVIEW.md`.
3. The relevant `Docs/handoffs/issue-*.md` (its **Resume here** section).
4. Print a short brief and continue from the recorded **Next action**.

The handoff doc + issue labels are the durable memory. Chat history is never required,
so switching models or harnesses loses nothing.

## 10. Hard constraints (do not violate)

Inherited from `AGENTS.md` and PRD §3.2 — restated for agents:
1. Never edit `project.pbxproj`.
2. `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, Swift 5 language mode; cross isolation
   like `OllamaProvider` (`await MainActor.run { … }`); mark pure helpers `nonisolated`.
3. Deployment target **macOS 13.0**: no `@Observable`, `onKeyPress`, two-parameter
   `.onChange(of:)`, `Inspector`, or newer APIs.
4. App Sandbox stays **off**; panels stay **non-activating**.
5. Preserve `///` doc-comment style on new public types and methods.
6. One task = one reviewable change. No unrelated refactors. Do not rename existing types.
